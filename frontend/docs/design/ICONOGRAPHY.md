# Iconography Guidelines

Icons should reinforce meaning clearly and quietly. They should feel consistent with the broader product language and support fast recognition.

## Preferred icon style
- simple outline icons
- consistent stroke width
- clear, modern geometry
- restrained visual weight

## Category icons
Use icons to help users quickly recognize knowledge domains such as:
- documents
- policies
- SOPs
- learning
- analytics
- AI assistance
- departments
- workspace tools

Category icons should be recognizable but not overly literal or decorative.

## Department icons
Departments should have distinct but calm icons that support scanning and organization. Avoid making them visually loud or playful.

## File-type icons
Documents should use visual file-type cues where meaningful:
- pdf
- docx
- spreadsheet
- presentation
- image
- archive
- folder

These icons should be clear and consistent with the rest of the system.

## Action icons
Use action icons for:
- search
- filter
- download
- share
- more actions
- move
- upload
- edit
- delete

Action icons should be unambiguous and easy to recognize in small sizes.

## Do and don’t
Do:
- use meaningful icons that support comprehension
- keep icon style coherent across the product
- use icons sparingly and intentionally

Don’t:
- use emoji as primary icons
- mix unrelated icon sets
- use heavy filled icons in dense interfaces
- add decorative icons that do not communicate something useful
